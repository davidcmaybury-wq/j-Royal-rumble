# Autohost step three — what was touched, what passed, what is owed

*From the design chat, 2026-09-14, against `c11a4f5`. Left in the working tree per `docs/autohost-contract.md`; nothing committed, nothing shipped. Built and tested in a local checkout, then written into this tree file by file; the suites below were run again here after the copy.*

## In one paragraph

An autohost match now runs the read-and-call loop with no human host: control goes to draw 1 at the bell; Mike hands the board over by name and starts the pick clock; the holder clicks a card on their own board (`player-pick`) or Mike picks after `pickSeconds`, with a nudge four seconds before; Mike announces the category and value, reads the clue, and the buzzers arm at the end of the clip through `runActivate` — the same `activate-buzzers {at}` send; a robot's answer is read aloud; a stumper is revealed and resolved by the host alone; a console's Correct / Wrong is confirmed aloud by Mike; Gene calls eliminations, entrances, field clears and overtime from `entry`, and the walk-in music plays after the name rather than under it; a robot's pick is performed. The board is synthesized in the background on deal and refresh, picked clues first, and a clue that beats the queue is read from the clock and counted. Every screen plays the clip from its own speaker and reports `heard {lateMs}`; the per-clip spread is on the host view and in the record. The starter of an autohost match lands on `/j/:code`, in full-board mode by default on a desktop.

## What passed

Every socket suite in `CLAUDE.md`'s list plus `guides`, `workflows`, `health`, `wrongs`, `tts`, `autohost`, `fullbuzzer`, `entrance`, `arcade`, `doubleresolve`, `when`, `reports`, `moved`, `security` (against a keyless server on 8097) and the four standalone suites; the harness prints its table unchanged. `latecomer` failed once on a server that had just booted and passed on the rerun — the `ECONNREFUSED`-shaped flake `CLAUDE.md` describes. `reap.mjs` fails on the baseline in this sandbox too (its spawned server on 8096 is not up within its wait), so it is not a regression but I did not get it green either; worth a look on the box.

`test/autohost.mjs` pins, over real sockets against the silent voice: draw 1 holds the board; every buzzer knows the computer hosts; the handover is by name and reaches everybody once; a non-holder's pick is refused by reason; the holder's click puts the clue up for all; category-and-value then the clue; the arm lands after the clip ends and within a beat (measured 256 ms — that is `SETTLE_MS` plus the socket); the arm is the same message a human host sends; a stumper is revealed only after the lights ran out and resolved by the host; Gene calls the entrance; the host view carries the `heard` spread (n, min, p50, max) and a second report from one client is ignored; a holder who does not call is nudged then picked for, and Mike says so; a player can buzz and a console can rule, Mike confirms by name, control passes and the board is handed on; the clip route 404s on a missing key and does not walk the filesystem; ending the match stops the host.

A smoke run with a stand-in piper (an executable that writes a WAV per line) proved the real-engine path: every line arrives with a `/clip/piper/<key>.wav` URL, the route serves `audio/wav` with a year-long immutable cache header, `fromClock` is 0, and the board backlog (57 jobs) drained with `depth` back to 0 before the first pick.

## Two things found while building

**Clip waits must be plain timers.** `emitClip` resolved its promise through `this.after`, which registers in `this.timers`; `onPicked` calls `clearTimers()` to cancel the pick clock, and a pick that landed while the nudge was still playing cleared the wait for the nudge itself. The chain then waited forever, every subsequent line silently never played, and the state said `reading` while nothing was read. It is a bare `setTimeout` now, with the reason in the code and in `CLAUDE.md`. This is precisely the shape the contract warned about: a silent failure with no signal; the test that caught it was the one asserting the category line arrives *after* a click.

**A full-mode buzzer sits in two rooms.** Four separate `io.to(room).emit` calls delivered each line twice to a buzzer that had asked for the board, and it would have played twice. One `io.to([rooms]).emit` dedupes per socket; proven with a two-buzzer check (2 and 2).

## What is owed, and what this could not measure

The two numbers step three owes the box are the ones that only a real room can produce, and neither exists yet. **The `heard {lateMs}` spread**: every buzzer and the console report it (the watch screen does not, on purpose — it has no clock sync, and a number off an unsynced clock would poison the spread); it is summarized per clip on `hostView().autohost.heard` and written into the record at match end as `autohost-summary`. `SETTLE_MS` is 250 and marked unmeasured; the spread from the first real match sets it. **The board backlog under a live match**: every background synthesis is a `synth` event in the record with its duration, character count and the queue depth behind it, and every pick that beat the queue is a `clip-wait` event with how long the room waited. In the stand-in run the whole board drained before the first pick; on the box at Piper's measured ~3 s a clue the first one or two picks of a fresh board may wait, and the record will say so.

The one thing I would watch on a real match that no test covers: Mike says "No, Name." *after* `runMarkWrong` has already reopened the race, so the room is racing while he speaks. That is correct for step three — a human ruled, the rules reopened the race, the voice is confirmation — and it goes away in step five, where the ruling is the host's and precedes the re-arm.

## Not done, on purpose

No mic, no judge, no objections, no spoken pick — steps four and five. No typed fallback. The console still exists and still works; it is simply not needed for anything but Correct / Wrong. Gene's voice is a variable, as you said.

## Two things to check first

Redirects and URLs: the setup page now navigates the starter to `/j/${code}` — a path built from the room code the page already had, never from input. The clip route takes `:engine` (must be in `ENGINES`) and `:key` (must match `^[0-9a-f]{40}$`) and resolves inside `DIR/engine/xx/`; a traversal attempt returns 404 before `existsSync`. `host-speaks` URLs are relative paths the server built from its own keys.

Silent failure paths: a voice that cannot synthesize is a `voice-fallback` event, a `fromClock` count on the host view, a `reason` on the message, and a nag on every buzzer; a browser that refuses to play says so on the buzzer with the browser's own reason; a hung or dead worker was proven in step two; a pick that beats the queue is counted; a refusal from any ruling the autohost drives is logged with the match id.
